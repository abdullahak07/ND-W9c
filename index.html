01 · FIREWALL FOUNDATIONS

A firewall is a controlled choke point.

It sits between networks, enforces local policy, provides a place for auditing, and adds another defensive layer. It can also be used internally to separate parts of an enterprise.

Remember: A firewall complements host security. It does not replace host security.
1

All traffic passes through

Inside-to-outside and outside-to-inside traffic should pass the firewall.

2

Only authorised traffic passes

Rules implement the organisation's security policy.

3

The firewall is hardened

The firewall itself must resist penetration.

02 · FIREWALL TYPES

Different firewalls inspect different context.

Start simple at the packet level, then add connection state or application awareness when the policy needs more context.

TypeLooks atStrengthMain trade-off
Packet filterPacket headersFast + simpleLittle upper-layer context
Stateful inspectionHeaders + connection stateTracks established sessionsMore state to maintain

Circuit gatewayConnection setupControls allowed circuitsUsually less payload inspection

Packet-filter attacks → countermeasures

IP spoofingOutside packet pretends to have an internal source IP.Drop “internal-source” packets arriving on the external interface.
Source routingSender tries to force a route that bypasses controls.Discard packets using source-routing options.
Tiny fragmentsTCP header information is split to evade header-based rules.Require enough transport header in the first fragment and track later fragments.

03 · INTRUSION DETECTION

Detection asks: “Does this behavior look like an intrusion?”

An IDS gathers evidence and provides real-time or near-real-time warning of attempts to access resources in an unauthorised way.

HIDS

Host-based IDS

Monitors one host, including processes, user accounts, files and system activity.

Best view: what actually happened on this host.
VS
NIDS

Network-based IDS

Monitors traffic on a network segment and analyzes network, transport and application protocols.

Best view: what crossed this network segment.

→
2AnalyzerDecide whether intrusion occurred

MISUSE DETECTION

Known pattern

Matches activity against rules/signatures that represent known attacks.

+ Fewer false alarms − Misses novel attacks
ANOMALY DETECTION

Different from normal

Builds normal behavior profiles and looks for significant deviations.

+ Can catch unknown attacks − False-positive / false-negative trade-off

NIDS: three signature styles

StringSuspicious text
PortConnections to risky/unused ports
HeaderDangerous or illogical header combinations
NIDS placement: Outside the main firewall · in the DMZ · behind internal firewalls near backbone/server networks · behind internal firewalls near departmental LANs.

07 · DENIAL OF SERVICE

DDoS attacks availability.

A DoS prevents legitimate users from using a service. A DDoS uses many compromised hosts to flood or exhaust target resources.

DIRECT DDoS

Attack hosts → target

Compromised zombie machines directly generate attack traffic. Multi-level bot structures make traceback harder.

REFLECTOR DDoS

Zombies → reflectors → target

Spoofed requests use the victim's address, causing uninfected reflectors to send responses toward the victim.

Three lines of DDoS defense

BEFOREPrevention & preemption

Resource policies, capacity planning and backup resources help the service endure attacks.

DURINGDetection & filtering

Detect suspicious traffic quickly and filter packets likely to be part of the attack.

DURING + AFTERTraceback & identification

Try to identify sources so future attacks can be reduced, though this is often too slow for immediate mitigation.
